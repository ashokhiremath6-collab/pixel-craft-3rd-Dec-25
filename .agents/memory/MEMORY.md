- [Drizzle migration journal must include all SQL files](drizzle-journal-completeness.md) — manually added SQL files in migrations/ are ignored by Drizzle migrator unless listed in migrations/meta/_journal.json; always add an entry when creating a new migration file.

- [Neon production DDL silently fails in Drizzle migrations](neon-production-ddl-failure.md) — ALTER TABLE in Drizzle migrations silently fails in Neon production (runtime user lacks DDL perms); server still starts, but ORM queries for the missing column then crash at runtime. Safe fix: make the migration a no-op and remove the column from the Drizzle schema until a proper DDL path is available.
- [Project type uses projectName not name](project-field-names.md) — Project objects have projectName (DB: project_name), not name. Using p.name causes undefined.localeCompare() crash in production when 2+ projects exist (sort comparator runs). Always use p.projectName in Project-typed arrays.
- [Org isolation: null-orgId safety net — vendors now strict-scoped](org-isolation-null-orgid.md) — getProjectsForUser still uses OR orgId IS NULL; vendors switched to strict eq(orgId) after migration 0052 cleaned nulls. - [Org isolation: admin fast-path bypasses org scope](org-isolation-admin-bypass.md) — storage methods with if(role==='admin') fast-paths that return all rows bypass org scoping. Fix: route admin through getProjectsForUser (org-scoped) and filter downstream tables by accessible project IDs.
- [Logo img tags need onError fallback](logo-onerror-fallback.md) — org logo <img> tags must have onError={() => setLogoError(true)} with logoError state guarding the condition; without it a stale logo_url in DB shows a broken image instead of org initials.

Workaround: place critical one-time DML (UPDATE/INSERT) directly in server/index.ts startup block with a WHERE EXISTS guard and try/catch — this bypasses the runner entirely and is idempotent.
- [createActivity must always include orgId](createactivity-orgid.md) — all 44 createActivity() calls lacked orgId; null-org activities bled across workspaces via users.orgId fallback.
